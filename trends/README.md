# 숏폼 유행 리포트 (trends/)

매일 아침 6시(한국 시간), 장르별 인기 숏드라마 쇼츠를 **한국·해외(미국·영어)** 로 나눠 모아 **형식(구조·길이·훅·편집 리듬)** 을 분석하고 텔레그램으로 보냅니다.
영상마다 **등장인물(cast)·흐름(flow)·결말(ending)** 을 따로 뽑아, 숏드라마 메이커 앱의 "유행 형식으로 새 대본"에서 인물·스토리·결말만 바꿔 쓸 수 있습니다.
해외 영상은 제목을 한국어로 옮기고(title_ko), 인물·흐름·결말을 한국식 설정으로 바꿔 적습니다. 해외 검색어는 config.yaml 의 `global_genres` 에서 고칩니다.
**인기 숏폼(숏드라마가 아닌 일반 인기 쇼츠)** 도 한국·해외로 함께 모읍니다: 상황극·동물·애니/캐릭터·썰·종합(인기 급상승 차트 포함). 검색어는 `popular` 에서 고칩니다.
영상마다 등장인물의 **종류(사람·동물·캐릭터·사물)와 외형(look)**, **장면별 대본(script)** 을 적고, 등장인물이 없는 영상은 cast 를 비워 둡니다. 숏폼 메이커 앱이 이 대본과 인물을 "비슷하지만 다른 내 것"으로 바꿔 씁니다.
운영비 0원 (유튜브 무료 키 + 제미나이 무료 키 + 깃허브 무료 Actions).

```
수집(collect.py) → 분석(analyze.py) → 텔레그램(notify.py) → data/ 저장
```

## 1. 준비물 (휴대폰으로 따라 하기)

### ① 유튜브 데이터 키 (YOUTUBE_API_KEY)
1. 휴대폰 크롬에서 `console.cloud.google.com` 접속 → 구글 로그인
2. 위쪽 **프로젝트 선택** → **새 프로젝트** → 이름 `shorts-trends` → 만들기
3. 왼쪽 메뉴(≡) → **API 및 서비스** → **라이브러리** → `YouTube Data API v3` 검색 → **사용**
4. **API 및 서비스** → **사용자 인증 정보** → **+ 사용자 인증 정보 만들기** → **API 키**
5. 만들어진 키 옆 **키 수정** → "API 제한사항"에서 **키 제한** → `YouTube Data API v3`만 체크 → 저장
6. 키 복사 (`AIza...`로 시작). 결제 정보는 넣지 않아도 됩니다.

### ② 제미나이 무료 키 (GEMINI_API_KEY)
1. `aistudio.google.com` 접속 → 구글 로그인 → 약관 동의
2. 왼쪽 메뉴 **Get API key** → **API 키 만들기** → 위에서 만든 `shorts-trends` 프로젝트 선택
3. 키 복사. 결제(Billing)를 연결하지 않으면 **무료 등급**으로만 쓰여 돈이 나가지 않습니다.
4. 무료 한도 확인: `aistudio.google.com/rate-limit` 에서 모델별 분당·하루 요청 수가 보입니다.
   - 공식 문서에는 무료 한도 숫자가 따로 적혀 있지 않고 "AI Studio에서 확인"이라고 되어 있습니다.
   - 하루 한도는 미국 서부 자정(한국 오후 4~5시)에 초기화되고, 키가 아니라 **프로젝트 단위**로 계산됩니다.
   - 무료 등급에 넣은 내용은 구글 제품 개선에 쓰일 수 있습니다 (여기선 공개 영상 정보만 보냄).

### ③ 텔레그램 (이미 봇이 있으면 건너뛰기)
1. 텔레그램에서 `@BotFather` → `/newbot` → 이름 입력 → **토큰** 받기 (TELEGRAM_BOT_TOKEN)
2. 만든 봇에게 아무 말이나 한 번 보내기
3. `@userinfobot` 에게 말을 걸면 내 **Id** 숫자가 나옴 (TELEGRAM_CHAT_ID)

### ④ 깃허브 Secrets 등록
1. 휴대폰 브라우저로 깃허브 저장소 열기 → (앱 말고 웹, 필요하면 "데스크톱 버전")
2. **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
3. 아래 4개를 이름 그대로 하나씩 등록

| 이름 | 값 |
|---|---|
| `YOUTUBE_API_KEY` | ①의 키 |
| `GEMINI_API_KEY` | ②의 키 |
| `GEMINI_API_KEY_2` ~ `GEMINI_API_KEY_5` | (선택) 추가 제미나이 키. 한 키의 하루 한도가 차면 다음 키로 넘어갑니다. **서로 다른 구글 클라우드 프로젝트**에서 만든 키여야 한도가 따로 계산됩니다 |
| `TELEGRAM_BOT_TOKEN` | ③의 토큰 |
| `TELEGRAM_CHAT_ID` | ③의 숫자 |

> 비밀값은 Secrets에만 넣습니다. 코드·로그에는 찍히지 않게 만들어 두었습니다 (유튜브 키는 주소가 아닌 헤더로 보내고, 오류 메시지는 가려서 출력).

## 2. 실행

- **자동**: 매일 한국 시간 아침 6시 (깃허브 사정으로 몇 분~수십 분 늦을 수 있음)
  - 자동 실행은 **기본 브랜치(main)** 에 이 파일들이 있어야 동작합니다.
- **수동**: 저장소 → **Actions** → **숏폼 유행 리포트** → **Run workflow**
  - "샘플 데이터로 시험"을 체크하면 유튜브 키 없이 분석·전송만 시험합니다 (data/에 저장 안 함).
- 실패하면 텔레그램으로 `❌ ○○ 단계 실패: 이유` 한 줄이 옵니다.
- 분석만 실패하면 수집 결과 요약은 그대로 오고, 맨 위에 실패 사유가 붙습니다.

### 내 컴퓨터에서 시험 (키 없이)
```bash
pip install -r trends/requirements.txt
python trends/scripts/collect.py --sample   # 샘플 raw.json
python trends/scripts/analyze.py --mock     # 가짜 제미나이 응답
python trends/scripts/notify.py --dry-run   # 보내지 않고 화면에 출력
```

## 3. 만들어지는 파일

| 파일 | 내용 |
|---|---|
| `data/YYYY-MM-DD/raw.json` | 수집 원본 (숏드라마 장르별 상위 10개 + 인기 숏폼 장르별 상위 8개, 인기 댓글 10개). 영상마다 `market`(kr/global)·`kind`(drama/popular) |
| `data/YYYY-MM-DD/analysis.md` | 영상별 "유행 형식 분석" 템플릿 + 전체 요약 |
| `data/YYYY-MM-DD/analysis.json` | 위 내용의 기계용 버전 (다음 날 "뜨는/식는 형식" 비교에 사용). `genre_info` 에 장르별 시장·종류, 영상마다 `format`·`audio`·`cast[{role,kind,who,look}]`·`script[{t,scene,line}]`·`watched` |
| `data/YYYY-MM-DD/status.json` | 단계별 성공/실패 |
| `data/history.csv` | 영상별 날짜별 조회수 누적 → 하루 상승 속도 계산 |

- **상승 속도**: 어제 기록이 있으면 `(오늘 조회수 − 지난 기록) ÷ 일수` = "실측", 처음 본 영상은 `조회수 ÷ 올린 뒤 지난 날` = "평균".
- 지난 7일 동안 잡힌 영상은 검색에 다시 안 나와도 조회수를 갱신합니다 (50개당 1단위라 거의 공짜).
- 유튜브 정책(데이터는 30일 안에 새로 받기)에 맞춰 30일 지난 `raw.json`과 누적 기록은 자동 삭제됩니다.
- 분석은 **형식만** 다루고, 제목·댓글·대사를 그대로 옮기지 말라고 제미나이에 지시합니다.

## 4. 하루 사용량

### 유튜브 할당량 (하루 10,000단위, 한국 오후 4~5시 초기화)
| 호출 | 단가 | 하루 횟수 | 합계 |
|---|---|---|---|
| search.list (검색) | 100 | 숏드라마 15개 + 인기 숏폼 10개 | 2,500 |
| videos.list (상세·인기 차트) | 1 | 50개당 1회 + 차트 4회 | ~15 |
| channels.list (구독자) | 1 | 1~3회 | ~3 |
| commentThreads.list (댓글) | 1 | 상위 영상마다 | ~130 |
| **합계** | | | **약 2,650단위 (26%)** |

- 검색어를 늘리면 1개당 100단위씩 늘어납니다. 최대 약 **85개**까지 가능하지만 수동 재실행 여유를 위해 **40개 이하**를 권장합니다.
- `quota_budget`(기본 9,000)을 넘을 것 같으면 남은 검색을 자동으로 건너뜁니다.
- 실제 사용량은 Actions 기록의 `[수집] 사용한 할당량` 줄과 텔레그램 맨 아래에 나옵니다.

### 제미나이 요청 수
| 요청 | 횟수 |
|---|---|
| 장르별 묶음 분석 (썸네일 3장 포함) | 숏드라마 10 + 인기 숏폼 10 |
| 전체 요약 | 1 |
| 영상 직접 보기 (`watch.max_total`) | 8 |
| **보통 하루** | **약 29회** |

- **영상 직접 보기**: 제미나이에 유튜브 주소를 넘겨 영상을 실제로 보게 하고, 장면별 대본과 등장인물 외형을 다시 적습니다 (`watched: true`). 실패하거나 한도가 차면 제목·댓글·썸네일로 추정한 분석이 그대로 남습니다. 두 번 연속 실패하면 그날은 더 보지 않습니다.
- 무료 한도가 빠듯하면 `watch.max_total` 을 줄이거나 0으로 끄고, 서로 다른 프로젝트의 키를 `GEMINI_API_KEY_2~5` 에 더 넣으세요.

- 요청 사이 15초 대기 → 분당 4회 이하.
- 429(한도 초과)면 60초·120초·180초 기다리며 최대 3번 재시도 → 그래도 안 되면 보조 모델(`fallback_model`)로 한 번 더 → 그래도 안 되면 분석 없이 수집 요약만 전송.

## 5. 바꾸는 법 (`trends/config.yaml`)

깃허브 웹에서 `trends/config.yaml` → 연필(✏️) → 고치고 **Commit changes**. 다음 실행부터 적용됩니다.

**검색어 바꾸기/추가**
```yaml
genres:
  복수극:
    - 복수 숏드라마
    - 참교육 숏드라마     # ← 한 줄 추가 = 하루 100단위 추가
  학교폭력 복수:          # ← 새 장르 추가
    - 학폭 복수 숏드라마
```

**인기 숏폼 검색어 바꾸기/추가** (장르 이름은 `인기 · ○○` / `해외 인기 · ○○`, 마지막 장르에 인기 급상승 차트가 들어갑니다)
```yaml
popular:
  kr:
    인기 · 요리:          # ← 새 장르 = 하루 100단위 추가
      - 요리 쇼츠
    인기 · 종합:          # ← 종합은 맨 아래에 둡니다
      - "#shorts"
```

**모델 바꾸기** (2026-11 공식 문서 기준 무료 등급 플래시 모델)
```yaml
gemini:
  model: gemini-3.8-flash          # 최신 안정판 플래시
  fallback_model: gemini-3.5-flash-lite
```
- `gemini-2.5-flash`는 2026-12-01부터 지원 종료라 쓰지 않습니다.
- 모델 오류(404)나 한도 오류가 계속되면 `aistudio.google.com/rate-limit` 에서 무료로 쓸 수 있는 모델 이름을 확인해 바꾸세요.

**그 밖에**
- `days`: 최근 며칠 영상 (기본 7) · `min_views`: 최소 조회수 (기본 1만)
- `rank_by`: `views`(조회수) / `ratio`(구독자 대비, 작은 채널 대박 찾기) / `velocity`(상승 속도)
- `my_background`: 아이디어를 바꿔 줄 내 배경 (배달 라이더·부동산·40대 가장)
- 실행 시간: `.github/workflows/trends.yml`의 `cron: "0 21 * * *"` (UTC 기준, 한국 = UTC+9)
